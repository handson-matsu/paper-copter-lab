# 紙コプター実験室 v0.2

固定カメラの静止背景との差分で紙コプターを追跡し、上下2本の判定ライン間を通過する時間を計測する試作版です。色の指定・マーカー・床検出・着地判定は使いません。撮影範囲より上から落としてください。計測する値は、手を離してからの全落下時間ではありません。

HTML / CSS / JavaScriptのみ。外部ライブラリ、AI、画像認識APIは不要です。映像は端末内で解析し、保存・送信しません。アクセスカウンターのみページ読み込み時に共通GASへGETを1回送信します。

## 使い方

1. カメラを台に固定し、人・手・動く背景・揺れるカーテンなどが映らない配置にします。
2. 「条件設定」に実験名、グループ、寸法、重り、落下高さ、メモを入力します。
3. 「カメラを起動」で許可し、紙コプターを映さず「背景を取得」を押します。約1.5秒の複数フレームから中央値背景を生成し、完全静止を待たず「待機中」になります。多少の動きがあっても取得をやり直しません。
4. 黄色の上側線・水色の下側線を指でドラッグして設定します。折りたたみ設定内のスライダーでも操作可能。上下の間隔は画面高の15%以上です。線や感度の変更で進行中の追跡は中断します。初回の待機移行に完全静止は不要です。
5. 「待機中」を確認して、紙コプターを撮影範囲より上から落とします。緑の枠は動体候補、太い青枠と円は追跡対象です。
6. 同じ対象の下向きの上側→下側通過を確認すると「計測完了」となり自動保存します。対象消失・曖昧さなどは「測定失敗」とし、時間を「—」にして数値を保存しません。
7. 完了・失敗後は、紙コプターを画面外へ片づけてください。背景との差分がなくなり800ms経過すると自動で次の「待機中」になります。対象や手が画面内に残る間は受付しません。
8. カメラを動かした、背景が変わった、回転した、カメラを再起動した場合は背景を取得し直してください。

背景取得時に物体を置いたままにすると、その物体も背景になります。できれば紙コプターを画面外に置いて取得してください。ただし完全静止は条件にしません。1つの画素で半数以上の取得フレームに同じ物体が写る場合は、その物体が背景に残ることがあります。映像フレーム自体が届かない場合は生成できません。

## 判定の仕様・誤検出対策

- 解析画像は長辺320px以下。約1.5秒、約100ms間隔、最大15フレームから画素ごとのRGB各チャンネルの中央値を計算します。動きがあっても取得時間をリセットしません。低fps時は3フレーム以上取得してから生成します。
- 差分閾値は感度50で36/255（以前は28/255）とし、カメラノイズへの許容を増やしました。各色チャンネルの差分の中央値で、画面全体の軽微な明るさ変化を補正します。大きな照明変化・広範囲の差分は無効とします。
- 待機中は約15秒の時定数で背景を緩やかに更新します。差分閾値を超えた画素と大きな背景変動は取り込まず、追跡中・完了後や失敗後の再受付待ちでは更新を停止します。
- 背景取得済みかどうかと動体検出が信頼できるかは別々に表示・判定します。待機中に大きな変動があっても取得済みの背景を失敗扱いにせず、検出側の理由を表示します。
- 閾値以下の差分、孤立画素、小さな連結成分、大きすぎる物体を除去。感度で差分閾値を調整できます。
- 画面上端付近から入り、上側ラインより上にある単独候補だけを追跡対象に取得します。途中から現れる動きだけでは計時しません。
- 位置・横方向の変位・予測位置・面積比・下降方向・フレーム間隔・複数候補の有無で同じ対象の継続性を確認します。画面上端で一部だけ写っている間の面積増加は限定的に許容します。
- 最低3フレームと一定の下降距離を確認した後、対象の**差分領域の中心**が上側ラインを下向きに横切った時刻を記録します。下側も同じ基準です。フレーム間を線形補間します。固定fpsから時間を換算しません。
- 消失は1フレームでも失敗にします。別物体への再取得は行わず、画面が静止するまでロックします。複数候補、位置飛び、面積の不連続、逆行、600ms以上の下降停止、180ms超の処理間隔、上側通過から10秒超も失敗です。
- 有効な上側→下側通過だけを履歴へ保存。失敗履歴・暫定の秒数は保存しません。手動で失敗値を確定する機能はありません。理由は画面・デバッグで確認できます。
- 画面回転・撮影サイズ変更・非表示化・カメラ停止は進行中の計測を中断し、背景を無効化します。ライン・感度の変更も進行中の計測を失敗にします。

同じ場所・大きさで物体が入れ替わる場合など、画像差分だけで同一性を完全に保証することはできません。影、反射、低コントラスト、分裂した機体像、回転による面積変化、背景の局所的な揺れで失敗や誤検出が起こり得ます。誤確定を避けるため判定は保守的です。線を上端に寄せすぎると事前追跡が不足します。実機で検出率と参照動画との差を検証してください。小数3桁の表示は精度保証ではありません。

## 保存・CSV・既存データ

実験条件は対象の追跡開始時にコピーし、測定日時、秒数、上下通過時刻、判定設定、方式 `background-lines-v1` とともにlocalStorageへ保存します。履歴の削除、UTF-8 BOM付きCSV、式として扱われやすいCSV文字列のエスケープを維持しています。

旧方式の履歴・条件は消しません。旧履歴は「旧方式の落下時間」、新履歴は「ライン間通過」と表示し、CSVにも計測方式を追加します。旧履歴の確認待ちを確定する操作は互換性のため残しています。両方式は測定区間が違うため混ぜて比較しないでください。

データは端末・ブラウザごとで同期しません。プライベートブラウズ終了・サイトデータ削除・容量不足に備えてCSVを定期保存してください。保存失敗は画面に通知し、現在の画面上の記録をCSVに出せます。

## iPad Safari・負荷

HTTPS上のSafariで直接開きます。背面カメラ優先、音声なし、`muted`・`playsinline` を使用。カメラ拒否・使用中・未接続・再生失敗を画面に表示します。許可待ちも停止で取り消せます。

解析は最大30回/秒、画像は最大102,400画素。中央値生成用に取得中だけ最大15フレームの縮小RGB画像（約4.39MiB）を保持し、生成後は解放します。常設の背景・差分・検出バッファは約1.96MiB、取得時の合計は約6.36MiB。一時RGBA画像と診断用画像はそれぞれ最大400KiBです。取得終了後は過去フレームを蓄積しません。重畳CanvasはDPR最大2・長辺1920px以下。停止時にトラックとコールバックを停止します。カメラデコード・GPU・ブラウザ内部のメモリはこの上限に含みません。

**実際のiPad/iPhone Safari、実カメラ、紙コプターの精度・発熱・電池消費は未検証です。** 合成画像の成功は実機精度を保証しません。

## 診断表示

「診断・デバッグモード」をオンにすると、背景取得の進捗／取得済み、照明補正後の差分画像（明るいほど差が大きい）、緑の候補枠、対象座標、候補数、判定理由、処理fps/msを確認できます。取得と検出の状態を見分けてください。背景の大部分が明るい場合はカメラや照明を調整し、必要なら再取得してください。診断用の画像描画は表示中だけ行います。

## 共通GASアクセスカウンター

既存の `access-counter.js` を維持しています。GAS本体・他リポジトリの変更なし。

```text
https://script.google.com/macros/s/AKfycbxssCIHsD-N97SHxNC_GN0ihYeC0qy-lb-EY0KmSs6Gnztaph1sITMerLVEnNWOGkYc/exec?app=paper-copter-lab
```

読み込み時1回のGET、`keepalive:true`、`mode:'no-cors'`、`cache:'no-store'`、`credentials:'omit'`。応答を待たず、再送・画面表示・独自ログ出力をしません。通信例外は無視し、カメラ・背景取得・ライン操作・計測・CSVでは追加送信しません。再読み込みは新たな1回です。映像・条件・測定結果は送信しません。GASの加算成功は保証せず、実GASへの加算は未検証です。

## 起動・GitHub Pages

コミット・push・公開設定は今回行いません。利用者が公開する場合は `main` の `/ (root)` をGitHub Pagesに設定し、HTTPSで開いてください。想定URLは https://handson-matsu.github.io/paper-copter-lab/ （今回到達確認なし）。

```text
index.html / style.css / app.js / tracker.js / camera-utils.js / access-counter.js / .nojekyll
```

すべて相対パス。ビルド不要。ローカルでは `python3 -m http.server 8765 --bind 127.0.0.1` で配信し `http://localhost:8765/` を開きます。ファイル直接オープンは不可。別端末からLANのHTTP URLではカメラを利用できないため、実機はHTTPSを使います。
