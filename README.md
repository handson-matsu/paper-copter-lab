# 紙コプター実験室：簡易帯計測 v0.3

**上側の判定帯で変化を検出したフレーム時刻を開始、以後の下側帯の反応フレーム時刻を終了とする簡易方式です。** 同じ物体の追跡・形状一致・方向推定は行いません。手や別の物体、照明変化でも誤計測し得ます。まず0.2〜0.8秒程度の通過を計測できることを優先しています。

## 操作

1. カメラを固定し「カメラを起動」。HTTPS上のSafari/ChromeまたはMacのlocalhostで許可します。
2. 紙コプターを映さず「背景を取得」。約1.5秒・最大15フレームの画素中央値で背景を生成します。多少の動きがあっても取得を完了します。
3. 黄色の上側帯・水色の下側帯を指でドラッグして配置。設定内のスライダーでも位置を変更できます。中心間隔は最低15%、各帯の厚さは映像高の12%です。
4. 上側帯から下側帯へ紙コプターを通します。上側反応で「計測中」、下側反応で秒数とmsを表示し自動保存します。検出時に帯と状態表示を約700ms緑色にします。上下それぞれの検出時刻も画面に残ります。
5. 完了・失敗後は600msの待機だけで次を自動受付。背景全体の完全静止や物体退出を再受付条件にしません。

## 判定仕様

- 背景と現在画像のRGB差分を使います。軽微な照明変化を補正し、感度50で差分閾値は36/255です。
- 各帯の**成分抽出前の差分マスク**を直接数え、3画素以上で発火します。連結成分・緑枠・物体数は関係ありません。
- 面積8%上限、全体変化16%制限、単一候補、事前追跡、形状・位置一致、下降速度、途中の物体消失は計測の必須条件から除外しました。診断用の領域抽出には旧面積集計が残りますが、計測には使いません。
- 上側の最初の反応時刻を開始とし、**以後のフレーム**の最初の下側反応時刻で終了。下側だけ先に反応しても開始しません。
- 両帯が同一フレームで反応しても0秒を捏造せず、次のフレームの下側反応を待ちます。大きな物体が両帯を覆えば短い誤計測が起こり得ます。
- 時刻は `requestVideoFrameCallback`、未対応なら `requestAnimationFrame` で実際に解析したフレームの単調増加時刻です。固定fps換算やライン中心通過の補間はしません。重複タイムスタンプは無視します。
- 0.1秒未満も保存し、秒を小数3桁、msも併記。JSONには開始・終了時刻と差分msを保持し、CSVにも時間(ms)を出力します。短い値を削除・長い値へ補正しません。
- 上側検出後5秒以内に下側を検出できなければ「測定失敗」。理由を表示し、数値は保存しません。帯外の動き、下側だけの反応、上側未検出も理由を表示します。
- 終了・失敗から600ms後は残留動作があっても再受付します。物体が上側に置かれたままだと再び開始し得ます。
- 待機中のみ非前景画素の背景を約15秒の時定数で更新。計測中と待機時間中は更新を止めます。
- 撮影は60fpsを希望し、各新規フレームを解析します。従来の固定30回/秒の間引きを削除しました。実fpsは端末依存です。縮小画像は長辺320px、描画CanvasはDPR最大2・長辺1920pxを維持します。

**撮影フレームの間に帯を通り過ぎると検出できません。** 12%の帯幅と60fps要求で漏れを減らしますが、すべての高速通過を保証しません。小数3桁は精度保証ではありません。手を離した瞬間から着地までの全落下時間ではなく、帯内で最初に変化を確認した時刻同士の差です。

## 表示・診断

緑枠は画面全体の動体反応です。緑枠の有無は帯の発火条件ではありません。上側／下側の反応・検出時刻・色変化を見てください。

診断モードでは差分画像、Canvas取得回数、入力変化、video時刻、RGB範囲、補正前後の差分、帯内変化画素数、開始・終了時刻を確認できます。「枠用候補」「枠用面積除外」は表示用であり、今回の計測を妨げません。

## 条件・履歴・CSV

実験名、グループ、寸法、重り、落下高さ、メモを維持。上側で計測を開始したときの条件を結果へコピーします。

localStorageに日時、秒・ms、開始終了時刻、帯設定、感度、方式 `background-bands-v1` を自動保存。状態は「簡易計測」として方向・同一物体を未確認である旨を残します。履歴削除、再読み込み後の保持、UTF-8 BOM付きCSV、CSV数式先頭のエスケープも維持しています。

旧方式の履歴は消しません。「旧・追跡ライン間通過」「旧方式の落下時間」と表示し、簡易帯方式とは区別します。旧履歴の確認待ち操作は互換性のため維持。測定区間が違うため混ぜて比較しないでください。CSVの既存列を維持し、末尾に時間(ms)を追加しました。

保存データは端末・ブラウザごとです。サイトデータ削除やプライベートモード終了で失うためCSVを定期保存してください。保存失敗は通知し、現在の記録をCSVへ退避できます。

## カメラ・実機の制約

背面優先・音声なし・muted・playsinlineを維持。エラー表示、許可待ちの停止、カメラ停止・回転・映像サイズ変更での中断と背景再取得を維持します。

**今回の簡易帯方式はiPad実機で未検証です。** Chromeの合成映像での成功はSafari実機の動作を保証しません。実際の紙コプターの検出率、誤計測、精度、発熱・電池消費を確認してください。背景画像は生成時のみ最大15枚の縮小RGB画像を保持し、生成後は解放します。診断の画像処理も負荷になるため不要時はオフにできます。

## 起動・テスト

ローカルは `python3 -m http.server 8765 --bind 127.0.0.1`、URLは `http://localhost:8765/`。別端末からHTTPのLANアドレスでカメラは利用できないため、iPadにはHTTPS公開先を使用します。静的ファイルは相対パス・ビルド不要です。コミット・push・公開設定は今回行いません。

Node.js 18以降で `node --test`。ブラウザテストはローカルサーバーを起動し、PlaywrightとChromeのパスを指定します。本番アプリにこれらの依存はありません。

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/playwright CHROME_PATH='/absolute/path/to/chrome' TEST_URL=http://localhost:8765/ node tools/browser-check.cjs
```

同じ環境変数で `tools/band-bypass-check.cjs`、`tools/camera-check.cjs`、`tools/access-counter-check.cjs`、`tools/background-check.cjs`、`tools/hand-reaction-check.cjs` も実行できます。GAS通信は差し替え、実アクセス数を増やしません。結果は [TEST_RESULTS.md](TEST_RESULTS.md) を参照してください。
