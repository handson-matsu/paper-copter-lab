# 紙コプター実験室

赤色マーカーの落下時間を、カメラ映像から端末内で計測する試作版です。HTML / CSS / JavaScriptのみ。計測機能に外部ライブラリ、AI、画像認識API、サーバーは不要です。映像を送信・録画しません。ページ読み込み時に共通GASアクセスカウンターへのGET通信を1回だけ行います。

## 起動とGitHub Pages公開

現時点ではローカル実装のみです。コミット・push・GitHub Pagesの公開設定は利用者が行います。この実装作業では行いません。

1. 利用者がこのリポジトリ直下のファイルをコミット・pushします。
2. GitHubの Settings → Pages → Build and deployment で「Deploy from a branch」を選択します。
3. ファイルをpushしたブランチと `/ (root)` を指定して保存し、Enforce HTTPSを有効にします。
4. 公開完了後の想定URL: https://handson-matsu.github.io/paper-copter-lab/ （未公開・到達未確認）。GitHubに表示される実際のURLを使用してください。

ローカル確認は `python3 -m http.server 8765 --bind 127.0.0.1` を実行し、PCの `http://localhost:8765` を開きます。ファイルの直接オープンではES Modulesやカメラが動作しません。iPad/iPhoneからLANのHTTP URLを開いてもカメラを利用できないため、実機ではHTTPS公開URLを使用してください。

## 使い方

1. 「条件設定」に実験名、グループ名、寸法、重り、落下高さ、メモを入力。
2. 端末を動かない台に固定。落下前の位置から床まで全体が映るようにし、背景の赤い物を除去します。赤色の十分な面積のマーカーを胴体下端に付けてください。
3. 「計測」でカメラを起動し、初回の許可を承認。背面カメラを優先しますが、端末によって選択されるレンズは異なります。
4. 「床の位置を指定」を押し、着地したマーカーの中心の高さを映像上でタップ。黄色い線が床の基準です。初期値のまま測ると確認待ちになります。
5. マーカーを上で静止させてから落とします。緑の円が検出位置です。画面高の6%以内の床付近で静止すると自動保存します。
6. 完了後に「次の測定を準備」を押して繰り返します。完了した記録はその場に保持されるため、持ち上げる動作で勝手に次の計測が始まりません。
7. 「測定結果」で確認待ちの理由を確認し、必要なら確定または削除。CSVはUTF-8 BOM付きです。

カメラ停止、画面非表示、画面回転、カメラ切断で進行中の測定は中断理由付きの確認待ちとして保存されます。戻ったら起動し直してください。回転後およびカメラを起動し直した後は、床を再指定してください。再起動時には前回の床指定を解除します。許可ダイアログの待機中も「停止」で取り消せます。取り消した後に許可が届いても、そのストリームは停止します。

## 検出・時刻の仕様

- 解析画像の長辺を320pxに制限（最大102,400画素）。縦映像でも高さが無制限に増えません。HSVの赤色帯・彩度・明度で二値化し、4近傍の連結成分を抽出。小さすぎる/大きすぎる領域を除外。
- 最初は最大の領域、その後は前回中心に近い領域を選択。位置飛びを棄却し、複数候補を不確実と扱います。消失500msで追跡対象を再取得。
- 時間は `requestVideoFrameCallback` の単調増加時刻を優先し、未対応ブラウザでは `requestAnimationFrame` を使用。固定fpsからの時間換算はしません。撮影要求は30fps、解析は最大30回/秒に制限し、重複した映像時刻の再解析も避けます。実際の解析頻度は端末やフレーム到着間隔によって低くなります。
- 開始は下方向の速度が閾値を超える状態が連続した時。開始時刻は、その連続下降区間の最初のフレーム時刻に遡ります。
- 終了は床付近で縦速度が閾値以下、かつ位置が狭い範囲内で静止した場合。終了時刻は静止区間の先頭で、静止確認の450ms（初期値）を含めません。
- 状態: 待機中 → 落下検出 → 計測中 → 着地判定中 → 計測完了 → 次の測定待機。下降の継続が不足したら待機中、静止が崩れたら計測中に戻ります。
- 消失、複数候補、フレーム間隔200ms超、計測途中の感度変更、15秒上限、床未指定、0.2秒未満、カメラ中断は確認待ち。中断・時間上限の値は最後に追跡できた時刻までの暫定値で、着地時間とは限りません。
- 判定設定変更は次の準備で反映。床の変更は計測中禁止。条件は落下開始検出時にコピーして記録します。
- 結果は日時、条件、秒数、判定状態、理由、開始・終了のページ基準時刻、設定とともにlocalStorageに保存。開始・終了msは同一ページ内だけで比較できる値です。
- CSVの先頭が数式記号の文字列にはアポストロフィを付加し、表計算ソフトによる式の実行を抑制します。


## GitHub Pages公開前の確認（2026-10-19）

実行に必要な6ファイルと配信設定ファイルを同じ階層に配置しています。ビルドやパッケージのインストールは不要です。

```text
index.html
style.css
app.js
tracker.js
camera-utils.js
access-counter.js
.nojekyll
```

CSS・JavaScript・モジュール間の参照はすべて相対パスです。ローカルで `/paper-copter-lab/` を再現し、必要なファイルの読み込みと合成カメラによる操作を確認済みです。`.nojekyll` を配置済み。GitHub Actionsや計測用のサーバー側APIは使用しません。アクセス数の記録にだけ既存の共通GASを使用します。Pages側の設定と実際のHTTPS配信は公開後の確認事項です。

iPad Safari向けに、カメラ起動ボタンから `getUserMedia` を要求し、`audio:false`・背面優先・`muted`・`autoplay`・`playsinline` を設定しています。HTTPSのページをSafariで直接開いてください。拒否・未接続・使用中などのエラーと例外名を画面に表示します。映像の再生失敗は取得失敗と区別します。ブラウザが返す例外名だけでは利用制限とユーザー拒否などの詳細原因を特定できない場合があります。

映像は縦横比を維持して中央に全体表示し、緑の円・床の線・床指定タップを同じ変換で扱います。余白のタップは無効です。画面回転や撮影サイズ変更で進行中の計測を中断し、再起動・床の再指定を案内します。画面の通常リサイズでは座標を再計算します。

負荷対策として検出用の型付き配列を再利用します。最大解析サイズで検出バッファは600KiB、`getImageData` の一時RGBAデータは最大400KiBです。画像データは履歴に保持しません。重畳CanvasはDPR最大2・長辺最大1920pxに制限します。カメラ停止で全トラック・解析コールバックを停止します。これらはアプリ側の上限であり、カメラ映像のデコードやブラウザ内部のバッファを含む総メモリ使用量の保証ではありません。

Safariの実装確認に使用した一次資料:

- [WebKit: A Closer Look Into WebRTC](https://webkit.org/blog/7763/a-closer-look-into-webrtc/)
- [WebKit: New video Policies for iOS](https://webkit.org/blog/6784/new-video-policies-for-ios/)
- [W3C: Media Capture and Streams](https://w3c.github.io/mediacapture-main/getusermedia.html)

## 共通GASアクセスカウンター

`access-counter.js` を `defer` スクリプトとして1回だけ読み込みます。既存教材 `chopsticks-game`・`stat-golf` と同じ共通GAS URLを使用しています。GAS本体や他リポジトリは変更していません。

```text
https://script.google.com/macros/s/AKfycbxssCIHsD-N97SHxNC_GN0ihYeC0qy-lb-EY0KmSs6Gnztaph1sITMerLVEnNWOGkYc/exec?app=paper-copter-lab
```

- ページ読み込み時のみGETを1回試行。アプリが付与するクエリは `app=paper-copter-lab` のみ。
- `keepalive:true`、`mode:'no-cors'`、`cache:'no-store'`、`credentials:'omit'`。非同期で送信し、応答・本文を待ちません。
- 同じページでスクリプトが重複実行されても再送しません。通信失敗・同期例外・fetch未対応も無視し、再試行や画面・ログへの独自の出力を行いません。
- カメラ起動・停止、測定・次の測定準備、条件変更、画面切替、記録確認、CSV出力では追加送信しません。
- 再読み込みは新しいページ読み込みなので、改めて1回試行します。配送・GAS側の加算成功は保証しません。
- カメラ映像・実験条件・測定結果はカウンターに送信しません。アクセス数も画面に表示しません。

カウンターテストは送信先をモック／ブラウザのリクエスト差し替えで処理します。実際のGASには接続しないため、テストでアクセス数は増えません。実環境でのGAS側の加算は未検証です。

## 保存と精度の制約

データは現在の端末・ブラウザ・オリジンごとです。別端末への共有・自動同期はありません。プライベートブラウズ終了、サイトデータ削除、保存容量不足で失う場合があるため、CSVを定期保存してください。保存失敗時は画面に通知し、現在のメモリ上の記録をCSVに出力できます。

**iPad Safari、iPhone Safari、PCの実カメラ、実際の紙コプターは未検証です。** 明るさ、マーカーの見かけの大きさ、赤色背景、手ブレ、回転、影、床の反射、遮蔽で誤認識が起こります。同じ場所に別の赤い物体があると追跡が入れ替わる可能性があり、すべての誤検出を自動検知できるわけではありません。

画面内の移動量から判定するため、カメラは固定し、床でマーカーが見える配置にしてください。時間分解能はカメラと処理間隔に依存します。表示の小数3桁は精度保証ではありません。実機で動画のコマ送りや別の基準計測と比較して閾値を調整してください。

## テスト

Node.js 18以降で `node --test` または `npm test`。本番アプリにはNode.js不要です。

ブラウザ通しテスト（開発時のみPlaywrightとChromeが必要）:

```sh
python3 -m http.server 8765 --bind 127.0.0.1
# 別のターミナルで、利用環境のパスを設定
PLAYWRIGHT_MODULE=/absolute/path/to/playwright CHROME_PATH='/absolute/path/to/chrome' node tools/browser-check.cjs
```

追加の座標・カメラ復帰テストと負荷測定:

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/playwright CHROME_PATH='/absolute/path/to/chrome' TEST_URL=http://127.0.0.1:8765/ node tools/camera-check.cjs
PLAYWRIGHT_MODULE=/absolute/path/to/playwright CHROME_PATH='/absolute/path/to/chrome' TEST_URL=http://127.0.0.1:8765/ node tools/access-counter-check.cjs
node tools/detector-benchmark.mjs
```

`camera-check.cjs` は既定で `/paper-copter-lab/` を開きます。通常のローカルサーバーでは上のように `TEST_URL` を `/` に設定してください。サブパス検証時はそのパスにリポジトリをマウントした静的サーバーを使用します。

`TEST_URL` で対象URLを変更可能。ブラウザテストは独立した新規ブラウザ領域で合成映像を使い、実データには触れません。すべてのブラウザテストでGAS通信を差し替え、実カウンターへの送信を防ぎます。結果と実機確認表は [TEST_RESULTS.md](TEST_RESULTS.md) を参照してください。
